# 연구실 일간보고의 배경과 작성 기준

## 배경 및 근거

프로젝트 `README.md`는 하루 동안의 연구 활동과 업무 메모를 바탕으로 맞춤법과 띄어쓰기를 수정하고, 의미를 유지한 자연스러운 일간보고를 작성하도록 정한다. 목적은 반복되는 문장 수정과 정리 작업을 줄이고 일관된 형식과 문체를 유지하는 것이다.

이 문서는 README의 원칙과 실제 일간보고 작성 중 사용자가 요청한 수정 사항을 정리한 참고 자료이다. 예시는 형식과 문체를 설명하기 위한 것으로, 이후 보고서의 활동 사실로 재사용하지 않는다.

## 사실 보존

- 실제 수행한 활동과 수치를 임의로 변경하지 않는다.
- 입력하지 않은 활동, 실험 결과, 시간, 날짜, 단위, 장비 사양, 원인, 성과 등을 추가하지 않는다.
- 어려움, 이해 수준, 느낀 점, 향후 계획도 원문에 있는 범위에서만 정리한다. 계획을 이미 수행한 활동처럼 쓰지 않는다.
- 전문 용어나 단위가 불명확하면 임의로 확장하거나 교정하지 않는다. 작성에 필요한 경우 사용자에게 질문한다.
- 학교명, 이름 등 개인정보를 추정하거나 임의로 포함하지 않는다. 사용자가 제공했더라도 보고서에 넣어 달라는 요청이 없으면 생략한다.

## 활동 구분과 제목

- 서로 다른 활동은 번호로 구분한다.
- 같은 실험에 관한 학습과 질의응답, 어려움, 느낀 점은 하나의 활동으로 묶는다.
- 실제 수정 사례에서는 막 교체 방법 학습과 해당 실험의 엑셀 입력 항목에 대한 질의응답을 `1. LAP-SCALE`로 통합했다.
- 제목은 `LAP-SCALE`, `토목기사 실기 공부`처럼 짧고 직접적인 활동명으로 쓴다. 세부 내용은 본문에서 설명한다.
- 사용자가 지정한 표기와 제목을 우선한다.

## 문체와 표현

- 맞춤법과 띄어쓰기를 수정하고, 문장의 의미를 유지하면서 자연스럽게 연결한다.
- 정중하고 간결한 보고서 문체를 사용하되, 불필요한 설명이나 과장된 표현을 피한다.
- 원문의 일상적인 경험을 지나치게 공식적인 행사나 절차처럼 표현하지 않는다. 질문을 받은 일을 `이번 점검`이라고 바꾸지 않는다.
- 예: `이번 점검을 통해 기록의 필요성을 느꼈습니다`보다 `질문에 답하지 못하면서 배운 내용을 정리해 두어야겠다고 느꼈습니다`처럼 실제 상황에 맞게 쓴다. 이러한 느낀 점도 원문에 근거가 있을 때만 포함한다.
- `짜르는 게`는 `자르는 데`, `여러번`은 `여러 번`, `교체할때 마다`는 `교체할 때마다`처럼 문맥에 맞게 다듬는다.

## 정보가 부족할 때

- 원문의 의미가 분명하면 불필요하게 질문하지 않고 정리한다.
- 활동의 내용이나 수치처럼 보고서의 사실에 영향을 미치는 정보가 모호하면 필요한 내용만 구체적으로 질문한다.
- 답변이 오기 전에는 추정으로 빈칸을 채우거나 사실을 확정하지 않는다.
- 보고서 작성에 필수가 아닌 날짜, 소속, 작성자 등의 정보가 없으면 생략한다.

## 최종 확인

- 같은 활동이 불필요하게 나뉘어 있지 않은가?
- 제목이 짧고 사용자의 명칭을 반영하는가?
- 맞춤법과 띄어쓰기가 정확하고 문장이 자연스러운가?
- `이번 점검`처럼 원문에 없는 상황을 덧씌우는 표현이 없는가?
- 활동, 수치, 실험 결과, 계획, 개인정보를 임의로 추가하거나 변경하지 않았는가?
- 사용자의 가장 최근 수정 요청이 반영되어 있는가?
